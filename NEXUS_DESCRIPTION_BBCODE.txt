[center][b][size=5]TESForm SafeLoad – Invalid Form Crash Fix[/size][/b]
[size=3]A narrowly scoped F4SE guard for an invalid TESForm editor-ID dispatch during save loading.[/size][/center]

[b]Release status[/b]
Version 0.1.0 is an experimental prerelease. The plugin has been observed installing its exact-signature hook on Fallout 4 1.10.163.0 and logged two intercepted invalid editor-ID dispatches (reason: UNREADABLE_VTABLE) on 2026-09-22. Those entries show that the guard substituted its placeholder. They do not establish that the complete save load succeeded or that the unguarded game would necessarily have crashed, so end-to-end crash prevention remains unverified.

[b]Compatibility[/b]
[list]
[*][b]Qualified target:[/b] Fallout 4 for Windows PC, runtime 1.10.163.0, with F4SE 0.6.23.0.
[*]The locally tested distribution was Steam. Other distributors using the same displayed runtime were not separately checked.
[*][b]Not qualified by this release:[/b] every other Fallout 4 runtime, including 1.10.980/1.10.984, 1.11.x, Fallout 4 VR 1.2.72, and Windows Store builds.
[/list]

“Not qualified” does not mean the crash is known to happen—or known not to happen—on another game version. The plugin can scan for a matching callsite on other PC builds, but a signature match alone is not proof of compatibility or successful crash prevention. The VR artifact is deliberately inactive.

[b]What this mod does[/b]
The crash path covered here occurs while Fallout 4 loads a save and handles a form-type-mismatch warning. The engine asks a TESForm for its editor ID through a virtual call. On the qualified 1.10.163.0 executable, that call is at Fallout4.exe+0x0CDF18A and uses vtable slot 0x1D0 (TESForm::GetFormEditorID). A stale or invalid form pointer or vtable can make this indirect call fault before the warning and changes-map cleanup finish.

TESForm SafeLoad searches the loaded game image for one unique callsite with the expected warning and cleanup structure. It does not patch when the signature is missing, ambiguous, or conflicting. At the guarded call, it checks the form memory, vtable, editor-ID function address, and returned string. If the target is invalid, the guard supplies the placeholder "<invalid-form>" so the existing warning and cleanup path can continue. Prevent mode also contains an access violation or in-page error raised inside the validated editor-ID function and records the incident.

[b]What it does not do[/b]
This plugin does not repair a save, rewrite a plugin, reconstruct a damaged form, or fix the data that produced an invalid reference. It covers only this save-load editor-ID dispatch; it is not a general save-corruption or invalid-form fix. The reported Far Harbor TESObjectCELL crashes are outside its scope.

[b]Installation[/b]
Install the release archive with Mod Organizer 2 or another mod manager. Its folder layout is rooted at the game's Data folder:
[code]
F4SE\Plugins\SaveLoadGuardF4.dll
F4SE\SaveLoadGuardF4.ini
[/code]
For a manual installation, extract the archive into Fallout 4's Data folder and launch the game through the matching F4SE loader.

The supplied INI enables Prevent mode. Observe mode still substitutes an invalid or un-callable editor-ID target with the placeholder; it cannot safely call an invalid function pointer to reproduce the original crash.

[b]Logs and verification[/b]
Logs are written to a fresh numbered file under Documents\My Games\Fallout4\F4SE\SaveLoadGuardF4.<n>.log; previous logs are not overwritten. A "working" log entry only proves the hook was reached. A "prevented" incident records a guard action but does not, on its own, prove that the full save load or later gameplay completed successfully.
